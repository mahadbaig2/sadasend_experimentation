# Competitor comparison

Checked 2026-11-25 UTC. This comparison uses current official documentation and public SDK source. Only SadaSend's hosted MCP path was tested live; Resend and Loops accounts were not tested. Pricing, limits, and dashboard behavior need separate verification. SadaSend's own competitor table was not used as independent evidence.

| Workflow | SadaSend | Resend | Loops |
|---|---|---|---|
| First SDK install | `npm install sadasend` (0.1.6); Python `pip install sadasend` (0.1.6). [TS source](https://github.com/SadaSend/sadasend-sdk-ts), [Python source](https://github.com/SadaSend/sadasend-sdk-python) | `npm install resend` (6.39.0). [Official Node SDK](https://github.com/resend/resend-node) | `npm install loops` (8.0.0), Node 20+. [Official SDK](https://github.com/Loops-so/loops-js) |
| First send | Both SadaSend SDKs include send examples; TS returns an `ok` result, Python a dict or exception. Hosted result untested. | Official readme shows `resend.emails.send` with text/HTML and a dashboard API key. Hosted result untested. | Official readme centers account API key and `sendTransactionalEmail`; hosted result untested. |
| Sender/domain step | [SadaSend docs](https://www.sadasend.com/docs) allow an onboarding sandbox sender for team addresses and test sinks, with a 100-message lifetime limit; production requires a verified custom domain. One sandbox email reached the approved Inbox after human approval. | [Resend verified-domain docs](https://resend.com/docs/dashboard/domains/introduction.md) require a domain you own and verify; subdomains are supported. | [Loops domain docs](https://loops.so/docs/sending-domain.md) require a domain you own and DNS verification before sending. |
| Error recovery | SadaSend TS typed result/errors and Python typed exceptions observed in source. Quality of real API errors untested. | SDK supports request `signal` and optional headers; live error quality untested. | SDK readme documents `APIError` (`json`, `statusCode`, raw body) and `RateLimitExceededError` (`limit`, `remaining`). Live error quality untested. |
| Webhooks | TS and Python signature helpers inspected; local signed fixture passed. Hosted delivery untested. | SDK includes webhook surface; current docs unavailable here. | Official SDK readme includes `verifyWebhook` and named verification errors. Hosted delivery untested. |
| Templates | SadaSend SDK lists template read/render/test methods. Hosted result untested. | Official SDK has email template related methods; exact workflow needs docs review. | Official SDK readme lists transactional email create/update/publish and send methods. Different model; equivalence needs hands-on test. |
| Agent/MCP | [Current SadaSend MCP docs](https://www.sadasend.com/docs/mcp) use streamable HTTP. Hosted initialization, preview, and an approval-mode send were tested. Scoped key exposed 11 tools; the docs list 12 in total. | [Resend MCP docs](https://resend.com/docs/mcp-server.md) offer a remote streamable HTTP server, OAuth, plugins, and skills. Not live tested here. | [Loops MCP docs](https://loops.so/docs/mcp-server.md) offer a remote streamable HTTP server for contacts, events, transactional email, and campaigns. Not live tested here. |
| Pricing, free tier, limits | Not verified | Not verified | Not verified |

**Product fit hypothesis:** SadaSend's scoped recipient policies and the approval hold tested here may be useful when teams let coding agents draft or send email. MCP itself is not unique: Resend and Loops both document hosted servers. Resend's official Node SDK has a concise first-send path and framework examples; Loops emphasizes contact, campaign, workflow, and published transactional-template flows. These are source observations and hypotheses, not measured superiority or deliverability claims. The failed SadaSend held-ID lookup is a real debugging drawback in this small test.
